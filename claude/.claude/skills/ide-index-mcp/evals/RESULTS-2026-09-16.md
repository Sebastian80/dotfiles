## What changed in the description

Added trigger vocabulary for the JetBrains built-in server's framework lookups (Symfony service, route,
Doctrine entity field, Twig template), and replaced the single pi-crawler exception with two: a factual
lookup wanted outside the current context goes to `/index-lookup`; broad multi-hop exploration in a
project with `.pi/mcp.json` stays with pi-crawler. The MANDATORY/MUST framing is unchanged; the July
result that stripping it cost four positives still stands.

## What the numbers say

The two extra hits are "why did phpstorm close my second project window" and "search the whole project
for the service id", both queries that name an IDE or framework concept the new wording now carries.
The two remaining misses are the same under both arms: "who calls X and what does it call itself" and
"check this file for errors", where the model opens Bash directly. Those are routing failures of the
hook's domain (`ide-first.sh` blocks the grep once it happens) rather than of the description, and the
July results already showed the skill is close to redundant as a router.

No negative triggered under either arm. The two debugger negatives correctly went to
`jetbrains-debugger`.

## Caveats

One run per query, so a single flip is noise-level; treat +2 as "not worse", not as a measured gain.
MCP was stripped, so this eval cannot see whether the runs would then have used the index tools well;
that is what the body and its subagent test on the same day cover.
